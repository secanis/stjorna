2. First-run setup:
   The first PocketBase superuser is created automatically on the first
   pod start from the Secret below (PB_SUPERUSER_EMAIL / PB_SUPERUSER_PASSWORD
   are mounted into the pod; entrypoint.sh runs `pocketbase superuser upsert`).
   The /setup wizard only has to sign in with those credentials and then
   walks through the storage, tenant, and admin-link steps.
{{- if .Values.ingress.enabled }}
   - Open https://{{ (index .Values.ingress.hosts 0).host }}/setup in your browser
{{- else }}
   - Port-forward the frontend (proxies /api/* to PocketBase):
     kubectl port-forward -n {{ .Values.namespace.name | default .Release.Namespace }} svc/{{ include "stjorna.frontend.fullname" . }} 8080:{{ .Values.frontend.service.port }}
   - Open http://localhost:8080/setup
{{- end }}
   - Step 1: sign in with the superuser credentials from step 3 below.
   - The wizard is locked once setup completes (instance_settings.setup_done);
     re-open /setup afterwards and it redirects to /login.

   Fallback: if the automatic superuser creation did not run (the wizard
   shows "No PocketBase superuser exists yet"), the bootstrap route
   requires a one-time setup token printed in the pod log:
     kubectl logs -n {{ .Values.namespace.name | default .Release.Namespace }} deploy/{{ include "stjorna.pocketbase.fullname" . }} | grep STJORNA_SETUP_TOKEN
{{- if .Values.pocketbase.setupToken.existingSecret }}
   (this release pins the token via Secret "{{ .Values.pocketbase.setupToken.existingSecret }}")
{{- end }}

5. Data persistence:
   - PVC "{{ include "stjorna.pocketbase.fullname" . }}" is annotated
     with `helm.sh/resource-policy: keep`. `helm uninstall` does NOT
     delete it. Storage retention across PVC deletion is controlled by
     the StorageClass's `reclaimPolicy` (set it to `Retain` to keep
     the underlying PV too).
   - The Namespace itself is also annotated with
     `helm.sh/resource-policy: keep` (T-06). Helm will never delete
     it; remove it by hand with `kubectl delete namespace ...` when
     you really want the cluster back.

6. Reset bootstrap (start over):
   To wipe the PB data and re-run the wizard, drop the PVC (the Secret is
   independent and can be re-read):
     kubectl delete pvc -n {{ .Values.namespace.name | default .Release.Namespace }} {{ include "stjorna.pocketbase.fullname" . }}
   The next pod start re-creates an empty pb_data directory, re-creates the
   superuser from the Secret, and the /setup wizard becomes available again.
